# max-hard-audit

One orchestrator, never audits in chat. Everything is a subagent. Loops of ten, until Max says stop.

**Argument:** the repo (and the scope: "contracts only" etc.). Read `~/.claude/audit-kit/INDEX.md` first if the target is Solidity/zk.

## Files (scratchpad, then copied home)

- `COMMON.md` — the binding lens rules, pasted into every lens prompt: READ-ONLY on the target (a live session may own it: never edit/build/commit/reset there); sample `git rev-parse HEAD` start + end (a moving HEAD is a finding); re-derive every cite at source (a cited line is not a read line); tag every hit `[NEW]` / `[KNOWN]` / `[OK]`; ≤ 60 lines; one line per finding: `sev | tag | claim | file:line | load-bearing fact | fix`; brevity (Max has AuDHD).
- `prior-findings.md` — every report ever produced, appended verbatim. Every lens dedups against ALL of it (including KILLED items) or refuted findings resurrect each round.
- `rN/lenses/<nn>-<slug>.md` — one file per lens per round.
- `iter/RULES.md` — verifier rules (ASSUME a claim is wrong and a defect is missing; CONFIRMED / WRONG / UNVERIFIABLE with re-derived evidence; MISSED DEFECTS last; ≤ 90 lines; READ-ONLY; write early, append as you go — rate limits kill agents).
- `~/<repo>-audit-consolidated-<date>.md` — THE table. One file, one fixer at a time. Back up `.rN.bak` before each fixer.
- `solutions/` — patches + README per fix owner (chain / guest / keeper / ops / docs); `VERIFY-*.md` next to them.
- `PROGRESS.md` — the builder's coordination file, one timestamped line per step; other agents read it, never write it.
- Memory: one `project` file per audit + index line; update after every round.

## The loop

1. **Round of ten lenses.** Pick ten territories nobody opened (grep prior lens titles). Each lens = one general-purpose agent (or `sp1-guest-auditor` for zk guests), prompt = COMMON.md + the territory + what is KNOWN there + "write ONLY `rN/lenses/…`". Launch all ten in one message. Territories that paid: linear reads of one lane end to end; guest↔chain↔keeper mirror parity; storage layout by hand-count; EIP-712 parity across repos; gates/allowlists; register vs tree; test truth (positive controls real?); deleted-guard forensics; live-state probes (cast, read-only); new code written tonight (adversarial); the plan itself as a security change.
2. **Append every report to `prior-findings.md`** the moment it lands. Archive to `~/<repo>-audit-round*-records/`.
3. **Fixer** (one agent, one file) folds the round into the table: re-verifies every cite before writing it, reports any brief item FALSE at source, recounts by the table's stated rule with arithmetic. Never two fixers on the file at once: gate the second on the file's mtime.
4. **Verifier pair** on the table every round: warm pair attacks the fix pass (the least-verified text) + a structural lens (premises, silences, interactions, rollback, worst-reader). Fresh agents each round; cross-verify from round 2.
5. **Cold close** for anything HIGH: a fresh pair, cold context, "survived N rounds; assume a defect remains". Cold pairs kept finding real things through round nine — keep going until a full pair adds nothing of substance.
6. **Solutions in parallel:** one designer per fix owner writes patches against a scratch copy (git apply --check on a fresh clone; cargo in scratch only; NEVER solc/forge in the tree without Max's go). Two verifiers per patch set, adversarial + apply-check; a cold pair before anything ships.
7. **Decision sheets** for every owner call (`max-decisions`): ≤ 12 decisions, money examples, one word each; ratifications collapsed into one row. Serve, watch the answers file, kill the server after.
8. **Design notes** per build lane → Max validates → build.

## Build phase (after "go")

- ONE builder agent, its own clone in the scratchpad (never the live tree), lanes fan out for code WRITING only, builds STRICTLY SERIAL AND FOREGROUND (Max's machine cannot fit two solc), lock file, `PROGRESS.md` line per step, no Co-Authored-By, never --force.
- Pre-flight the toolchain (forge/cargo/cargo prove versions, pinned rustc present) before any long build.
- Land lanes in dependency order; 0 `.orig/.rej` in any commit (grep case-insensitively — BSD patch prints lowercase "failed"); wire generators re-run from the spec (never hand-edit generated blocks); fixtures regenerated by emitters, never hand-edited; storage tail-append only, freed slots renamed in place; lens pins for every new slot.
- **Fidelity verify** every range before push (read-only: each commit vs its patch/note/ruling; trailers; strays; storage hand-count; wire copies; role gates; deleted selectors vs the ruled list). Verdict PUSHABLE / NOT YET.
- **Push incrementally** to main when Max rules so: forge green modulo the named pre-existing reds + cargo green on the range; fast-forward only; `PUSHED <sha> → origin/main` in PROGRESS; the auditor edition of the table is re-stamped at each freeze sha (every cite re-derived at origin/main; no lane/scratchpad cites).

## Watchdogs and limits

- Liveness = file mtimes, git log in the lane clones, `ps` for solc/cargo — never transcript silence. A 9-minute background sleep re-arms the pull; task output files stay 135 B until completion.
- Rate limits kill batches: when Max says the limit is back, relaunch every cut agent in RESUME mode from its on-disk state (clone, PROGRESS, partial report) — trust the disk, not the summary.
- Verifiers that lack the Write tool return text: save it yourself.
- Misaddressed messages happen when ids look alike: keep a launch-order list of ids and roles.
- Foreign builds in other sessions' worktrees contend for CPU: report them to Max, never kill another session's process.

## Cadence that worked

- ≤ 10 agents live; every response requests every item that does not depend on another's result; nothing else.
- Every finding routed the same minute it lands: code defects → the builder/lane; doc defects → the fixer; owner calls → the next sheet.
- Memory line after every push, every sheet, every relaunch.
